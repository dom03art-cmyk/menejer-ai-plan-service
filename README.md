# Менежер AI — Төслийн тооцоо/график/Word угсрах сервис

Энэ бол Make.com-той хамт ажиллах жижиг HTTP сервис. Make.com өөрөө Python/Node
код ажиллуулж чадахгүй тул (график зурах, санхүүгийн томьёо бодох, Word (.docx)
файл MNS 5140:2021 стандартын дагуу угсрах гэх мэт) — эдгээрийг хийж өгөх
зорилготой.

Сервис 3 үндсэн үйлдэл хийнэ:

1. **`POST /calc/finance`** — НПВ, ДТОХ (IRR), эргэн төлөгдөх хугацаа,
   ашгийн хугарлын цэг (BEP), ROI, DSCR тооцоолол.
2. **`POST /calc/payroll`** — цалингийн НД, ХХОАТ, ажил олгогчийн зардлын
   тооцоо.
3. **`POST /docx`** — дээрх тооцоо болон Claude-ийн бичсэн текстийг нэгтгэж,
   MNS 5140:2021 форматтай (А4, Arial, 1.15 мөр хоорондын зай, автомат
   "ГАРЧИГ" гэсэн TOC-той) бэлэн Word файл болгож буцаана. Шаардлагатай бол
   QuickChart.io ашиглан график зургийг автоматаар зурж баримт руу шигтгэнэ.

## 1. Байршуулах (deploy) — Render.com дээр (үнэгүй төлөвлөгөө)

Танд хостинг байхгүй байгаа тул хамгийн энгийн, үнэгүй эхлэх сонголт бол
**Render.com**. Алхмууд:

1. **GitHub дээр repo үүсгэх.** [github.com](https://github.com) дээр
   бүртгэлгүй бол шинээр үүсгэнэ. Дараа нь энэ `menejer-ai-plan-service`
   фолдер доторх бүх файлыг (`server.js`, `lib/`, `package.json`,
   `render.yaml` гэх мэт) шинэ repo-д push хийнэ (`node_modules`-г
   оруулах шаардлагагүй — `.gitignore`-д орсон байгаа).

2. **Render.com дээр бүртгүүлэх** — [render.com](https://render.com), "Sign
   up with GitHub" гэдгийг ашиглавал repo-г шууд холбоход хялбар.

3. **"New +" → "Web Service"** дараад дээрх GitHub repo-г сонгоно.

4. Тохиргоо:
   - **Runtime:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `node server.js`
   - **Instance Type:** Free
   - (Хамт орсон `render.yaml` файлыг Render автоматаар танина — ихэнх
     талбарыг өөрөө бөглөнө.)

5. **Environment Variables** хэсэгт `API_KEY` нэртэй хувьсагч нэмээд, урт
   санамсаргүй нууц үг (жишээ нь 32 тэмдэгттэй санамсаргүй мөр) оруулна.
   Энэ түлхүүрийг Make.com-оос хүсэлт илгээхдээ `x-api-key` header-т
   дамжуулна — ингэснээр танай сервисийг өөр хэн ч дуудаж чадахгүй болно.

6. **"Create Web Service"** дараад ~2-3 минут хүлээнэ. Амжилттай болмогц
   танд `https://menejer-ai-plan-service-xxxx.onrender.com` маягийн URL
   өгнө.

7. Шалгах: `https://<таны-url>/health` хаягийг браузераар нээхэд
   `{"status":"ok", ...}` гарч ирвэл амжилттай.

### ⚠️ Чухал анхаарах зүйл: Free tier "унтдаг"

Render-ийн үнэгүй төлөвлөгөө 15 минут дуудлага ирээгүй бол сервисээ
"унтуулдаг" (sleep). Дараагийн хүсэлт ирэхэд сэрэхэд 30-50 секунд орчим
зарцуулдаг ("cold start"). Энэ нь Make.com-ийн automation-д хэрэглэгч
удаан хүлээх шалтгаан болж болзошгүй. Үүнийг шийдэх хоёр арга:

- **Хямд арга:** Make.com дээр өөр нэг энгийн Scenario үүсгэж, 10 минут
  тутам `/health`-рүү HTTP GET хүсэлт явуулж сэрүүн байлгах (Make-ийн
  үнэгүй багц дунджаар хангалттай квот өгдөг).
- **Тогтвортой арга:** Render-ийн "Starter" төлөвлөгөө руу шилжих
  (сар бүр ~$7) — унтахгүй, хамгийн найдвартай.

## 2. API-ийн ашиглалт

Бүх endpoint JSON хүлээж авна, JSON эсвэл файл буцаана. `API_KEY`
тохируулсан бол бүх хүсэлтэд (`/health`-ээс бусад) `x-api-key` header
заавал байх ёстой.

### `POST /calc/finance`

```json
{
  "cash_flows": [-70000000, 22000000, 28000000, 33000000, 35000000, 36000000],
  "discount_rate": 0.15,
  "annual_debt_service": 15000000,
  "break_even": { "fixed_costs": 8000000, "unit_price": 5000, "unit_variable_cost": 2000 },
  "roi_year": 5
}
```

Буцаана: `npv`, `irr`, `payback_period_years`, `total_investment`,
`cumulative_cash_flow_by_year`, `dscr_by_year`, `break_even_point`, `roi`.

### `POST /calc/payroll`

```json
{
  "positions": [
    { "title": "Технологич", "count": 1, "gross_salary": 1800000 },
    { "title": "Худалдагч", "count": 2, "gross_salary": 1200000 }
  ]
}
```

Буцаана: байр тус бүрийн НД/ХХОАТ/цэвэр цалин, нийт сарын/жилийн зардал.

### `POST /docx`

`meta` (нүүр хуудасны мэдээлэл) болон `sections` (гарчиг/параграф/жагсаалт/
хүснэгт/график/pagebreak блокуудын массив) хүлээж авна. Хариу нь шууд
`.docx` файл (binary) байна. Жишээ бүтэц:

```json
{
  "meta": {
    "doc_title": "БИЗНЕС ТӨСӨЛ",
    "project_name": "... төслийн нэр ...",
    "org_name": "... компанийн нэр ...",
    "location": "Улаанбаатар хот",
    "filename": "Компани нэр - Бизнес төсөл.docx"
  },
  "sections": [
    { "type": "h1", "text": "НЭГ. ТӨСЛИЙН ТОВЧ ТАНИЛЦУУЛГА" },
    { "type": "p", "text": "..." },
    { "type": "h2", "text": "1.1. Зорилго" },
    { "type": "bullet", "text": "..." },
    { "type": "table", "headers": ["...", "..."], "rows": [["...", "..."]] },
    { "type": "chart", "type": "bar", "title": "...", "labels": ["..."], "series": [{"name": "...", "values": [1,2,3]}] },
    { "type": "pagebreak" }
  ]
}
```

Гарсан баримт нь MNS 5140:2021-ийн дагуу (А4, margin 30/15/20/20мм, Arial,
1.15 мөр хоорондын зай, эхний хуудсан дээр "ГАРЧИГ" гэсэн автомат
агуулгын хүснэгттэй) бэлэн байдаг. **Chart блокууд зөвхөн сервис бодит
интернэттэй хост дээр (жишээ нь Render) ажиллаж байх үед л зурагддаг** —
энэ орчинд (Claude-ийн sandbox) QuickChart.io-руу гарах сүлжээ хаалттай
тул локалаар шалгах боломжгүй байсан; deploy хийсний дараа эхний удаа
бодит график орсон .docx-оор шалгаж үзэхийг зөвлөж байна.

## 3. Дараагийн алхам

Энэ сервис зөвхөн "тооцоолол/график/docx угсрах" хэсгийг хийдэг. Claude
API дуудаж бодит агуулга (зах зээлийн шинжилгээ, стратеги гэх мэт) бичих
хэсэг нь Make.com Scenario дотор шийдэгдэнэ — тухайн дизайны талаар
дараагийн зөвлөмжийг тусад нь өгнө (бүлэг тус бүрээр Claude API дуудаад,
эцэст нь энэ сервисийн `/docx`-руу нэг удаа илгээх бүтэц санал болгож
байна).
