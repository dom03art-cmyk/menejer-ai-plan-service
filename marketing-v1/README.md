# marketing-v1: маркетингийн төлөвлөгөөний урсгал

Менежер AI-ийн хоёр дахь бүтээгдэхүүн. `mongol-marketing-plan` skill-ийн бүтэц, дүрмийг энэ үйлчилгээнд зөөсөн хувилбар.
Бизнес төслийн урсгал (`plan-v2`)-тай ижил зарчмаар ажиллана: бүлэг бүрийг тусдаа Claude дуудлагаар бичнэ, бүх тоог код бодно, Word ба PDF-ийг код угсарна.

## Бизнес төслийн урсгалаас тусгаарлалт

- Бүх файл `marketing-v1/` хавтас дотор. `plan-v2/` болон үндсэн хавтсын файлууд өөрчлөгдөөгүй.
- Цорын ганц өөрчлөлт: `server.js`-д 2 мөр нэмнэ (доор). `try/catch`-тай тул энэ хавтас алдаатай байсан ч сервер асаж, бизнес төсөл хэвийн ажиллана (туршсан).
- Бүх зам `/mkt/...`-ээр эхэлнэ. `/jobs/...` замуудтай давхцахгүй.
- Өөрийн дараалалтай, өөрийн webhook-той (`MKT_DONE_WEBHOOK`). `MAKE_DONE_WEBHOOK`-ийг хэрэглэхгүй тул бизнес төслийн Make scenario-д дохио очихгүй.
- `MKT_ENABLED=1` гэж тохируулах хүртэл шинэ ажил хүлээж авахгүй (унтраалга). Код байршуулсан ч юу ч идэвхжихгүй.
- Бизнес төсөл боловсруулагдаж байвал маркетингийн ажил түүнийг дуустал хүлээнэ (санах ой, API-ийн хязгаарыг булаалдахгүй).
- Өнгө, график, PDF-ийн тохиргоог модулийн түвшинд хадгалдаггүй, `plan-v2`-ийн тохиргоог өөрчилдөггүй.
- Сервис унтрах үед `process.exit` дууддаггүй: унтраалтыг `plan-v2` хэвээр удирдана.
- `plan-v2`-оос зөвхөн уншиж ашигладаг: `claude.js` (API дуудлага), `util.js` (Messenger-ээр илгээх), `theme.js` (өнгө сонгох), `pdf.js` (фонтын тохиргоо).

Үлдэх хамаарал: нэг сервер, нэг API түлхүүрийг хуваалцана. Маркетингийн ажил ажиллаж байх үед шинэ бизнес төсөл орж ирвэл хоёулаа зэрэг явна (санах ой, API-ийн хурдны хязгаарыг хуваана). Мөн `plan-v2/claude.js`, `util.js`-ийн функцийн нэр, параметрийг хожим өөрчилбөл энэ модулийг дагуулж засна.

## server.js-д нэмэх мөр

`app.use(require("./plan-v2"));` мөрийн ДАРАА:

```js
// marketing-v1: маркетингийн төлөвлөгөөний урсгал (бүх зам /mkt/...). Ачаалж чадаагүй ч бизнес төслийн урсгалд нөлөөлөхгүй.
try { app.use(require("./marketing-v1")); } catch (e) { console.error("[marketing-v1] ачаалж чадсангүй:", e.message); }
```

Шинэ npm багц шаардлагагүй (docx, pdfmake, @anthropic-ai/sdk аль хэдийн суусан).

## Байршуулах дараалал (бизнес төсөлд саадгүй)

1. `GET /jobs-status` → `safe_to_deploy: true` болохыг хүлээнэ (боловсруулагдаж буй төсөл байхгүй үед).
2. `marketing-v1/` хавтсыг repo-д нэмж, `server.js`-д дээрх 2 мөрийг нэмээд push хийнэ. `MKT_ENABLED` тохируулаагүй тул юу ч идэвхжихгүй.
3. Deploy дууссаны дараа `GET /health`, `GET /jobs-status` хэвийн эсэхийг шалгана. Render-ийн log-д `[marketing-v1] ачаалж чадсангүй` гэсэн мөр байхгүй байх ёстой.
4. Render-т `MKT_ENABLED=1` нэмнэ (энэ нь сервисийг дахин асаана, тиймээс мөн `safe_to_deploy` үед).
5. `psid`-гүй туршилтын ажил явуулж (доор), PDF-ийг татаж шалгана.
6. Чанар хангалттай болсны дараа л Make, Messenger-т холбоно.

Буцаах: `MKT_ENABLED`-ийг устгахад шинэ ажил авахаа болино. Бүрэн буцаах бол `server.js`-ийн 2 мөрийг хасна.

## Замууд (бүгд x-api-key шаардана)

| Зам | Үүрэг |
|---|---|
| `POST /mkt/jobs` | body: `{psid, conversation}` эсвэл `{psid, assumptions}`. `psid` өгөхгүй бол Messenger-ээр юу ч илгээхгүй (туршилт). `notify:false` бол эхлэх мессеж илгээхгүй |
| `GET /mkt/jobs/:id` | төлөв, үр дүн, чанарын шалгалтын тэмдэглэл (`qc`) |
| `GET /mkt/jobs/:id/file` | Word файл. `?type=pdf` бол PDF |
| `GET /mkt/status` | ажиллаж буй, дараалалд буй ажил, `safe_to_deploy` |

## Орчны хувьсагч (Render)

| Нэр | Утга | Тайлбар |
|---|---|---|
| `MKT_ENABLED` | `1` | Заавал. Байхгүй бол `POST /mkt/jobs` 503 буцаана |
| `MKT_DONE_WEBHOOK` | Make webhook | Сонголтоор. Дууссан, алдаа гарсан, тасалдсан үед `{product:"marketing", status, psid, ...}` илгээнэ |
| `MKT_MAX_PARALLEL` | `1` | Зэрэг боловсруулах маркетингийн ажил |
| `MKT_CONCURRENCY` | `2` | Нэг ажил доторх зэрэг бичих хэсгийн тоо |
| `MKT_YIELD_TO_PLAN` | (хоосон) | `0` бол бизнес төслийг хүлээхгүй |

`ANTHROPIC_API_KEY`, `FB_PAGE_TOKEN`, `API_KEY`, `ADMIN_PSID`-ийг одоо байгаагаар нь ашиглана.

## Урсгал

1. `intake.js`: ярианаас таамаглал гаргана. Сарын төсвийн дээд хязгаарыг код сахина. Захиалагчийн зарын бодит тайлан хангалттай бол таамаглалыг бодит тоогоор солино.
2. `calc.js`: төсөв, юүлүүр, CAC, ROAS, LTV, 3 хувилбар (skill-ийн Python скрипттэй ижил үр дүн өгдгийг тулгаж шалгасан).
3. `research.js`: web хайлтаар зах зээл, өрсөлдөгчийн судалгаа (амжилтгүй бол судалгаагүй үргэлжилнэ).
4. `chapters.js`: эхлээд стратегийн тойм, дараа нь `outline.js`-ийн хэсэг бүрийг тус тусад нь бичнэ. Зарын headline 40, тайлбар 30 тэмдэгтийг код шалгана.
5. `blocks.js`, `charts.js`, `document.js`, `pdf.js`: календарьт огноо, гараг нэмэх, график, Word, PDF.
6. Messenger-ээр PDF, Word илгээж, сануулга мессеж бичнэ.

## Туршилт

Claude, Messenger дуудахгүй локал туршилт (угсралт, тооцоог шалгана):

```
MKT_MOCK=1 node marketing-v1/test/run-local.js
```

Render дээр бодит туршилт (Messenger рүү илгээхгүй, `psid`-гүй):

```
curl -X POST https://<service>/mkt/jobs -H "x-api-key: ..." -H "Content-Type: application/json" \
  -d '{"assumptions": <marketing-v1/test/menejer-assumptions.json-ийн агуулга>}'
```

Дараа нь `GET /mkt/jobs/:id` → `done` болмогц `GET /mkt/jobs/:id/file?type=pdf`.

## Хийсэн шалгалт

- Тооцоо: Python скрипттэй тулгахад зөрүүгүй.
- Туршилтын агуулгаар бүтэн урсгал: Word (бүтцийн шалгалт давсан), PDF (гарчиг хуудасны дугаартай) гарсан.
- Туршилтын горимд бизнес төсөл ба маркетингийн ажлыг нэг серверт зэрэг ажиллуулахад хоёулаа амжилттай дууссан.
- Модулийг зориуд эвдэж асаахад сервер хэвийн асаж, `/jobs-status` ажилласан.

## Одоогоор туршаагүй, хийгээгүй зүйл

- **Бодит Claude дуудлагаар бичсэн агуулга.** Локал орчинд API түлхүүргүй тул зөвхөн туршилтын агуулгаар угсралтыг шалгасан. Бичвэрийн чанар, хуудасны тоо, нэг төлөвлөгөөний API зардал, хугацааг Render дээрх эхний бодит туршилтаар хэмжинэ.
- **График.** QuickChart-ийг локал орчноос дуудаж чадаагүй. Баганан, шугаман, дугуй график нь `plan-v2`-той ижил хэлбэртэй. Юүлүүр ба байрлалын график шинэ төрөл: амжилтгүй бол юүлүүрийн график орхигдоно, байрлалын зураг хүснэгтээр гарна (баримт эвдрэхгүй).
- **Word-ийн гарчиг.** Хуудасны дугаарыг Word нээхэд шинэчилдэг талбараар тавьсан (PDF-д бодит дугаартай).
- **Засвар (revision).** v1-д хэсэгчилсэн засварын урсгал байхгүй.
- **Make, Messenger-ийн холболт.** Ярилцлагын асуулт, төлбөр, бүтээгдэхүүн сонгох салааг хараахан хийгээгүй.
- **Байгууллага, хувь хүний төрөл.** Код дэмжинэ, бодит жишээгээр туршаагүй.
